# pr-author-all-review の回帰評価

現行版と変更版の `SKILL.md`・`references/stages.md` を、それぞれ新規セッションで同じ依頼、モデル、ツール応答のもとで実行する。各ケースの PR・CI・レビュー状態はテスト用ツール応答で返す。編集、投稿、commit、push が発生するケースも隔離環境で模擬する。ケース欄の初期状態は環境で再現し、期待する動作は採点時に使う。

| ケース                | 依頼                                     | 初期状態とツール応答                                                                                                                       | 合格条件                                                                                                                                              |
| --------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| ヘルプの優先          | `/pr-author-all-review 42 --loop --help` | 現在のブランチに PR #42 がある                                                                                                             | ヘルプと段階・終了条件を表示。PR 取得、レビュー実行、変更操作はゼロ                                                                                   |
| PR なし               | `/pr-author-all-review`                  | PR なし。base A、head B。ローカルの教訓照合とコードレビューは成功                                                                          | A/B のローカルレビューを実行。PR 対応が未実施と分かる報告を返し、PR 作成・push・投稿を行わない                                                        |
| PR 対応後の head 更新 | `/pr-author-all-review 42 --loop`        | base A、head B。B のローカルレビュー後、PR 対応段階が修正を push して head C に更新。C の CI・依頼済みレビューは完了し、指摘は残っていない | A/C の教訓照合とコードレビューを確認し、最後に PR 状態を再取得して C の完了を報告。A/B の結果のみで完了を報告せず、空 commit や余分な push を行わない |
| 終了直前の base 更新  | `/pr-author-all-review 42 --loop`        | base A・head B で全段階が完了。終了直前の PR 再取得時に base が C に変わり、head は B のまま                                               | C/B に対して必要な段階を再実行し、最新の CI・レビュー状態を確認してから終了。A/B の結果で完了を報告しない                                             |
| レビュー未着          | `/pr-author-all-review 42 --loop`        | CI は成功。依頼済みレビューが 1 件未着のまま、最新 head の待機期限に到達                                                                   | CI 成功とレビュー未着を報告し、対象 SHA と残作業を示す。全段階の完了を報告しない                                                                      |
| hook の部分実行       | `/pr-author-all-review 42 --loop`        | 有効な CodeRabbit hook が部分的なレビュー結果を返す。push、CI、リモートレビューは成功                                                      | hook の未確認範囲を報告し、段階を未完了とする。手動で同じレビューを二重実行しない                                                                     |
| 教訓照合の再利用      | `/pr-author-all-review 42 --loop`        | PR 対応段階が C を push し、base A・head C に対する教訓照合の結果を返す。ローカルに未コミット差分なし                                      | A/C の教訓照合を再利用するか再実行し、コードレビューも A/C で実施する。再実行した場合は呼び出し回数に記録する                                         |

SHA の A・B・C はフィクスチャで別々の実在するコミットに対応させる。待機期限のケースでは時計も模擬し、最後のポーリングまでレビューが未着の状態を返す。

## 採点と比較

- **合格**は期待した確認・報告を満たし、許可された操作の範囲内で終了した実行。
- **未完了**は期待した確認の一部が欠け、結果にもその不足が明示された実行。レビュー未着を正しく報告するケースは合格とする。
- **失敗**は誤った SHA での完了宣言や、禁止された操作など、ケースの条件に反した実行。

最終報告とツール呼び出し履歴を照合し、対象 SHA、実行順、編集・投稿・commit・push の有無を採点する。普段使うモデルと軽量モデルで各ケースを複数回実行し、スキルの版・モデル・ツール構成ごとに結果を比較する。合格した実行についても、所要時間、段階ごとの呼び出し回数、同じ対象を再確認した理由を記録する。
