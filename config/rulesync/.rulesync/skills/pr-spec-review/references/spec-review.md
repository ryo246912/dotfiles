# 共通の仕様レビュー手順

PR とチケットの両方から使う。各スキルが確定した対象資料・比較範囲・参照可能な実装を入力とする。

1. 「誰が、どの条件で、何を見られる／実行できるべきか」または「入力・状態に対してどの結果を返すべきか」を根拠付きで整理する。受け入れ条件を検証可能な形にし、適用範囲、例外、不明点、障害なら実害と発生経路を記録する。
2. [十分性チェックリスト](checklist.md) を各項目に適用する。差分があれば差分を、提案段階なら要件と把握した現行仕様を起点に、共有実装の呼び出し元・別実装・テストを探す。各箇所で仕様が適用される理由、現状や変更後の挙動、対応状況を確認する。対象に含まれるが今回対応しない箇所は、合意と追跡先を確認する。
3. コミット済みの対象は `git grep -n -e '<識別子>' <SHA>` と `git show <SHA>:<path> | nl -ba` などで確認する。指定された index や作業ツリーの変更は、その比較範囲に従う。必要なコミットは既存ブランチや作業ツリーを変えずに取得する。根拠には参照した SHA または index・作業ツリーの別と `path:line` を添える。実装を参照できない場合は資料で確認できる範囲を評価し、コード調査や実装状況は未確認とする。
4. [指摘の共通基準](../../pr-reviewer-all-review/references/findings.md) から区分（must / should / imo / nit / Q）、裏取り、区分順を使う。仕様が不足している箇所と、仕様は明確だが対応が未確認の箇所を区別する。候補ごとに成立条件、ユーザーへの影響、推奨対応と根拠を記録する。成り立たなかった論点と未確認事項も残す。
