# PR 作者のレビューをまとめて実行する

## ヘルプ・引数

使い方: `/pr-author-all-review [PR番号またはURL]`

| 引数           | 意味                                                 |
| -------------- | ---------------------------------------------------- |
| `-h`, `--help` | この節とレビュー段階一覧・終了条件を説明して終了する |
| PR 番号・URL   | 対象 PR。省略時は現在のブランチの PR を使う          |

ヘルプは他の引数より優先し、PR の取得、各 skill の実行、編集、監視、commit・push・投稿を行わない。不明なオプションでも処理せずヘルプを表示する。オプションはこの skill が解釈し、対応していない引数を各 skill や CLI に渡さない。

既定で、該当するレビュー段階を順に実行し、指摘の修正・検証・commit・push、最新 head の CI と再レビューの確認を完了条件まで繰り返す。自律的に判断できる項目は妥当な推奨案に沿って修正・検証し、コミットと対象 PR ブランチへの通常の push まで進める。対象範囲はユーザーの指定に従う。

## レビュー段階と責務

最初に [レビュー段階一覧](references/stages.md) を読む。一覧の順に既存 skill の本文を読んで実行し（有効時の push 前 CodeRabbit レビューは既存 hook に任せる）、各段階の対象差分、指摘、採否、修正、未確認事項を記録する。この skill はレビュー基準を複製せず、順序・再実行・終了判定だけを管理する。専門レビューは関連ファイルが変わった段階だけを実行する。マージ先リポジトリに一致する環境別設定があれば、その表も参照する。

- 対象リポジトリ・PR・`baseRefName` / base SHA・head リポジトリ / ref / SHA とローカルの未コミット差分を確認し、各段階へ同じ比較範囲を渡す。各周の開始時と commit・push 後に head SHA を更新し、古い SHA を再利用しない。教訓照合には `--base <選択PRのbase SHA> --head <head SHA>` を渡し、code-review にも同じ範囲を指定する。pr-author-fix の worktree・push 先の検証手順に従い、他者の変更を混ぜない。PR が存在しない場合はローカルで実行可能な段階だけを行い、PR 対応は未実施と報告する。PR を自動作成しない
- `/code-review` は利用環境に提供される既存のものを使う。提供されない場合は同じ差分を直接レビューし、代替したことを報告する。実行失敗を成功扱いせず、調査しても検証できない部分は未完了とする
- PR 上のコミットしかレビューできない段階は、ローカル検証と許可済みの commit・push 後に実行する。未コミットの修正をレビュー済みと扱わない
- 各段階は結果を呼び出し元へ返し、この統合 skill を再起動しない。不要な重複投稿・同じ差分の重複レビューを避ける

## 修正・検証・再レビューの進め方

1. 各周の開始時に、対象 PR があれば pr-author-fix のコンフリクト対応手順に従う。ユーザーの明示的なスキップ指定は PR 対応段階にも引き継ぐ。解消により base または head が変わった場合は比較範囲を取り直す。その後、一覧のローカルレビュー段階を実行し、各段階の妥当な指摘の修正・検証を先に完了する。対応可能なローカル指摘の修正を済ませてから pr-author-fix の待機へ進む。指摘ゼロの PR でも教訓照合とコードレビューを省略しない。
2. ローカル指摘の修正・必要なテストと lint が完了したら commit・push し（有効時は CodeRabbit hook の指摘にも対応）、その後に PR 対応段階を実行する。判断困難な項目は段階ごとに判断待ちとして記録し、依存しない修正・検証を進める。PR 対応段階の判断待ちも集約し、各段階で個別の回答待ちにしない。判断待ちに依存する操作は保留する。教訓の記録は既存の lessons-record の手順に従う
3. 修正・他者の push・base 更新で対象差分が変わったら、一覧の再実行条件に従って影響する段階をやり直す。変更がない場合は空 commit や不要な push を行わない
4. 同じ最新 head と差分に対する適用対象の全段階の結果が揃い、未対応指摘がなく、コンフリクトが解消済みか明示的にスキップされ、必要な CI と依頼済みレビューが完了したら、状態を再取得して終了する。`pr-author-fix` が変更を push した場合もローカルレビューを取り直す。単に同 skill が戻ったことを成功条件にしない

待機間隔・最新 SHA の確認・未着レビューの扱いは pr-author-fix に従う。待機期限は最新 head ごとに共有し、段階を再実行してもリセットしない。既定は 60 秒間隔、30 分まで。時間切れ、外部障害、依存ツール不足、PR の closed / merged は残作業と対象 SHA を報告して終了する。同じ原因の修正が 2 回続けて失敗した場合や、設計の大幅変更・矛盾する指摘・権限不足は判断待ちにする。対応可能な作業を終え、残りがユーザーの判断に依存する時点で、待機期限を待たず、該当項目・根拠・選択肢・推奨案（示せる場合）とその影響をまとめて最後に判断を委ねる。未完了の段階があれば完了とは報告しない。force push、テスト・check の無効化、自動マージは行わない。
