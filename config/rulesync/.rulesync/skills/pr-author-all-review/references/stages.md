## 専門レビューの対象と再実行

レビュアー向けにも実行する段階は、共通列に「レビュアー」と記載する。

- 対象差分の追加・変更・削除・リネームと、対象に含まれる staged・unstaged・未追跡ファイルを列挙する。削除とリネームでは旧パスや削除内容も参照する。関連ファイルが変更された場合だけ段階 4〜11 を選ぶ。パスだけでは判断できない行は diff の内容を確認する。裏取りのために関連する未変更ファイルも読んでよい
- 1〜3 は対象差分または base が変わったら再実行する。4〜11 は差分または base SHA が変わるたびに適用条件と根拠を確認し、影響を受けた段階を再実行する。差分が同じでも、base 側の関連する未変更ファイルや結論の前提が変わっていないかを確認する。該当がなくなった段階は対象外に更新する。対象外・未実施・実施済みは理由とともに記録する
- Ponytail を含む各段階には同じ比較範囲と該当ファイルを渡し、読み取りと検証に絞って、指摘の根拠・影響・未確認事項を返す。自動修正、依存導入、設定変更、外部投稿は専門段階の中で行わない。同じ根拠・修正で解消する指摘は一般レビューと統合する。ミューテーションテストは利用可能な環境で、重要な変更箇所に絞る。実行できなかった検証は結果に明記する
- 同じ対象差分を pr-fix 内で教訓照合済みなら段階 1 に再利用できる。未コミット差分や base が変わったら再実行する

## 環境別の追加段階

このスキルの `SKILL.md` と同じディレクトリの `*.md` が対象。環境ごとに `work3.md` のようなファイルを作る。`SKILL.md` と `*.md.example` は追加表の対象外。dotfiles のスキルディレクトリにある `work3.md.example` を同じ場所に `work3.md` としてコピーし、実際のリポジトリと追加段階を記入する。Rulesync はこのファイルをスキルと一緒に配布する。

1. PR のマージ先リポジトリ、PR が無い場合は作業リポジトリの `origin` を `ホスト/所有者/リポジトリ` に正規化する。HTTPS と SSH の表記差、末尾の `.git` とスラッシュを吸収する。GitHub のホスト・所有者・リポジトリ名は大文字小文字を区別しない。リポジトリを特定できない場合は追加段階を適用しない
2. ローカル設定にある「対象リポジトリ」のリストと完全一致したファイルだけ、そのファイルの「追加レビュー段階」の表を適用する。実行中のスキルのディレクトリだけを参照し、レビュー対象の PR や作業ツリーから同名のファイルを探さない。ファイル名の辞書順、表の行順で評価し、変更パスまたは変更内容が条件に一致した行を追加する
3. 同じスキルが複数の行や共通段階に一致したら、対象と確認観点を合わせて 1 回だけ実行する。設定が無い場合、一致するリポジトリや関連差分が無い場合は対象外とする。設定の誤りやスキルが無く実行できない行は、該当するファイル名・行と理由を報告する

## 有効時の push 前 CodeRabbit レビュー

CodeRabbit は skill ではなく、既存の `preToolUse` hook（`config/devcontainer/scripts/coderabbit-review.py`）が `git push` の前に実行するレビュー段階。hook が登録され、CLI が利用可能で、対象リポジトリに `.coderabbit.yaml` がある場合のみ動く。無効な環境ではこの段階を適用対象外として記録し、有効化や追加インストールは行わない。

- 既存 hook に実行を任せ、同じレビューを手動で二重実行しない。対象は送信元のコミット済み HEAD で、未コミット差分は対象外
- hook が結果を返して push を止めたら、内容を確認し、妥当な指摘を修正・検証・commit してから通常の push を再実行する。この対応も妥当な推奨案に沿って自律的に行い、変更で影響するローカルレビュー段階も適用条件に従って再実行する。判断待ちの項目は統合スキルの最終報告に引き継ぐ
- 既存 hook が同じ送信元 HEAD のレビュー済み記録により省略した場合は、同じ SHA のレビュー結果と指摘の対応状況を確認できれば「実施済み（結果を再利用）」と記録する。hook の記録は SHA と時刻だけなので、前回の結果や指摘の対応状況を確認できない場合は「未完了（結果未確認）」とする。記録の削除や hook の無効化で push を通さない
- 今回の差分で push が不要な場合は「対象外（push なし）」と記録し、段階 12 の新しい結果は完了条件に含めない。同じ HEAD にすでに未対応の指摘や未完了の試行があれば、その状態を引き継ぐ
- CLI の失敗や部分的なレビューは、push が続行できても未確認範囲を報告する。取得できた指摘は評価する。失敗を完了の根拠にしない

リモートの CodeRabbit bot レビューはこのローカル段階と別であり、push 後は pr-fix の段階で CI・他の依頼済みレビューとともに待つ。hook の詳細は `docs/rulesync.md` を参照する。
