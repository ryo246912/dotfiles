# レビュー段階一覧

| 順序 | 段階                                                                         | 適用条件と役割                                                                                                                |
| ---- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1    | [チケット・要望の取得](../../ticket-spec-review/references/ticket-intake.md) | 指定された資料と直接の要望を読み、両レビューに共通の目的、制約、根拠、未確認事項を揃える。                                    |
| 2    | [ticket-spec-review](../../ticket-spec-review/SKILL.md)                      | 期待される振る舞い、適用範囲、考慮漏れと受け入れ条件を確認する。確定した条件と未解決の前提を段階 3 へ渡す。                   |
| 3    | [ticket-uiux-review](../../ticket-uiux-review/SKILL.md)                      | ユーザーに見える画面・情報・操作に関係する要望で実施する。要求を UI/UX の観点から評価し、画像付きの実現案と実装難易度を返す。 |

各段階の実施状況と対象外・未実施の理由を記録する。仕様の未確定事項があっても、その事項に依存しない UI/UX の論点は確認する。実現案によって仕様の前提が変わる場合は、統合結果にその条件を残す。
