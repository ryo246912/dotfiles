# チケット・要望の統合レビュー

## 引数

チケット URL・識別子、Slack のメッセージリンク、または要望の本文を受け取る。URL と補足の併記もできる。`-h` / `--help` は他の引数より優先する。引数と段階一覧を説明して終了し、チケット取得やレビューは行わない。不明なオプションでも処理を開始せず、使い方を示す。

## レビュー段階と責務

[レビュー段階一覧](references/stages.md) の順に実行する。共通の入力は一度取得し、各スキルへ対象資料、目的、既知の制約と前段の結果を渡す。利用可能な完全名で呼び出すか、配置済みのスキル本文を読んで該当手順を実行する。

## 結果のまとめ方

冒頭に結論と推奨を置き、要求の考慮漏れ、既存 UI/UX との整合性、画像付きの実現案、仕様と実装の難易度、結論に影響する未確認事項をまとめる。同じ論点はまとめて出典スキルを併記する。各案の画像、操作できる試作、根拠へのリンクを引き継ぐ。実行できなかった段階は理由を示す。結果はユーザーへ返し、外部サービスへの投稿やチケットの編集は別の依頼として扱う。
