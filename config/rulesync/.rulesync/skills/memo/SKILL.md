# メモ書き出しスキル

会話中に行った PR レビュー・設計調査・アーキテクチャ分析の結果を、プロジェクトの `plan/` ディレクトリに記録する。同じカテゴリの新規メモは連番にし、番号が大きいほど新しく作成されたメモと分かるようにする。

## 手順

### 1. 保存先と新規作成・追記の判定

ユーザーが保存先や加筆先を指定している場合はその指定を優先する。指定がない場合は `plan/` を使い、無ければ作成する。

1. 保存先にあるメモを Glob で全件確認し、ファイル名・内容から同じカテゴリのメモを特定する。カテゴリはタイトルの話題ではなく、既存の命名規則（`spec`、`memo` などの種類）に従う
2. 既存メモの続きや修正を求められた場合は、そのファイルに追記する。加筆先の指定がなく候補が複数ある場合は、同じカテゴリのうち番号が最大のファイルを読む
3. 新しい話題・調査結果のメモを作る場合は、同じカテゴリの最大番号に 1 を足して新規作成する。別の話題でも同じカテゴリなら連番を共有し、話題ごとに開始番号へ戻さない
   - `00-spec-first.md` があれば、次は `01-spec-second.md`、その次は `02-spec-third.md`
   - `10-memo-first.md`、`11-memo-second.md` があれば、次は `12-memo-third.md`
   - 欠番は埋めず、既存ファイルの改名・上書きはしない。番号は数値として比較し、最低 2 桁のゼロ埋めにする
4. 同じカテゴリのファイルがなければ、既存のカテゴリ開始番号の規則に従う。通常のメモは `10-memo-<topic>.md` から開始する
5. 本文の冒頭に作成日時・更新日時をタイムゾーン付きで記載し、追記時は更新日時を更新する。番号は作成順、更新日時は追記を含む新しさの判断に使う

### 2. 既存ファイルを必ず Read する

既存ファイルに追記する場合は、**ファイルを Read せずに Edit / Write しない。** 既存の内容・目次・セクション番号を把握してから追記する。新規作成の場合は、採番したパスが未使用であることを確認する。

### 3. 目次にエントリを追加する

既存の目次がある場合、新しいセクション番号とリンクを追加する。新規作成の場合は、本文に対応する目次を作る。

例：

```md
## 目次

1. [既存のセクション](#1-既存のセクション)
2. [新しいセクション](#2-新しいセクション) ← 追加
```

### 4. 末尾に本文セクションを追記する

以下の構成でセクションを書く:

```md
---
# N. セクションタイトル

## N-1. 背景・概要
...

## N-2. 詳細

...

## N-3. 推奨・まとめ

...
```

## 注意事項

- コードスニペットは「現状」「比較」「推奨」の3点セットで書くと再利用しやすい
- 「なぜそうなっているか（背景・理由）」を必ず含める
- 「次にどうすべきか（推奨）」を短期・長期に分けて書く
- 一時的なタスク固有の情報（特定のバグ詳細など）は含めない
