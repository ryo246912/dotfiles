# スクリーンショット付きHTMLレポート

## 出力ファイル

- 保存先: 対象リポジトリの `.pr-reviewer-artifacts/<PR番号>/<実行識別子>/`
- ファイル名: 入力PRの `<PR番号>-<PRタイトル>.html`。例: `123-検索条件を追加.html`
- 実行識別子には日時等を使い、前回のレポートを上書きしない。
- タイトル中の `/`・`\`・`:`・`*`・`?`・`"`・`'`・バッククォート・`$`・`<`・`>`・`|`・制御文字は `-` にする。前後の空白・末尾の `.` を除き、ファイル名全体がUTF-8で255バイト以内になるようタイトル末尾を文字単位で短縮する。空なら `変更内容` を使う。
- PRタイトルをシェルへ直接展開しない。ファイルパスはファイルAPI等で安全に組み立てる。

## HTMLの要件

UTF-8の単独で読めるHTMLを作る。`lang="ja"`、viewport、ページタイトルを設定し、CSSはHTML内に置く。
外部CDN・スクリプト・追跡用リソースには依存させない。PR本文・画面文言・入力値などはHTMLエスケープし、文字列をそのままHTMLとして挿入しない。
URLは `http` / `https` のみリンクに使い、認証情報や秘密のクエリパラメータを転記しない。

確認済みの各項目に、実際の操作後に撮影した結果画面を `<figure><img ...><figcaption>...</figcaption></figure>` として貼る。
PNG/JPEG等の画像をbase64のdata URIで埋め込み、HTMLを移動しても見えるようにする。
キャプションには確認項目・操作直後の状態・何が確認できる画像かを記載する。
一覧表の証拠欄から該当画像へページ内リンクを張る。画像は横幅に収め、拡大して読める大きさで表示する。
秘密情報や個人情報がある画面は安全な範囲で撮影し直す。用意できない画像を捏造したり別項目の証拠に流用したりせず、撮影不可の理由を明記する。

## 本文の構成

### 対象と結果の概要

- 入力PRへのリンク・タイトル
- 検証に使った最上位PRへのリンク・stackの根拠
- 確認対象の変更範囲
- head SHA・環境との対応確認状況
- local／staging、検証URL、実行日時、使用したChromeの接続方法
- アカウント別名・ロール・テナント（秘密値は書かない）

### 準備済みデータ

用途、ID・表示名、状態・関連データ、開くURL、作成／再利用を表にする。

### 手動確認の手順

シナリオごとに、使用するアカウント別名とロール、最初に開くURL、画面上の文言を使った操作順、入力例・準備済みデータ、期待結果を番号付きで記載する。
到達までの画面も必要に応じて画像付きで示し、ユーザーが同じ状態から確認を続けられるようにする。

### 実行結果とスクリーンショット

確認項目・仕様の根拠、操作、期待結果、実結果、判定、証拠画像へのリンクを表にする。
判定は PASS / FAIL / BLOCKED / NOT RUN。実行していない項目をPASSにしない。
表の下に各項目のスクリーンショットとキャプションを配置する。

### 不一致・未確認事項

再現手順、期待と実際の違い、不具合／環境不足／仕様不明の区別、続行に必要な条件を記載する。
base比較は未実施のため、PR起因かは未判定とする。

### 後片付けと次回への引き継ぎ

残したデータ、削除方法、元に戻した既存データを記載する。
設定補完・教訓追記を行ったかと、その要点だけを書く。設定内の認証情報は転記しない。

## 出力後の確認

接続中のChromeで生成したHTMLを表示できる場合は、画像・リンク・表を確認する。
ツールや接続先の制約でローカルHTMLを開けない場合も、HTMLの構文・画像埋め込み・参照先を確認し、ブラウザでの表示は未確認と明記する。
最後に生成したHTMLのパスをリンクで渡す。
