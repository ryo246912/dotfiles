# レビュー段階一覧

| 順序 | skill / 手順                   | 実行条件と役割                                                                                                                                                                          |
| ---- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 直接レビュー・教訓照合         | [共通手順](findings.md) の直接確認と教訓照合で差分、関連コード、テスト、過去の指摘と規約を確認                                                                                          |
| 2    | code-review                    | 同じ PR 差分を読み取り専用で確認できる場合に実行。利用できない場合は直接レビューに代替し、理由を報告                                                                                    |
| 3    | ponytail-review と専門レビュー | [作者向けの段階一覧](../../pr-author-all-review/references/stages.md) で共通列が「レビュアー」の行を順に使う。Ponytail は差分を確認し、専門レビューは関連ファイルが変わった場合だけ実行 |
| 4    | 環境別の追加段階               | `work3.md` などの追加レビュー表で対象リポジトリと変更ファイルが一致する行を実行                                                                                                         |
| 5    | pr-reviewer-behavior           | 変更された振る舞いを実環境で確認でき、起動済み環境・対象 SHA・必要な操作権限が揃えば一度だけ実行。`-nb` / `--no-behavior` 指定時は対象外                                                |
| 6    | pr-reviewer-brief              | `-br` / `--brief` 指定時に解説を作り、段階 5 の確認結果を引き継ぐ                                                                                                                       |
| 7    | 候補提示・壁打ち・投稿         | 裏を取った候補を提示。ユーザーの選択後に通常は draft を作る。公開は明示指定と本文の確認が必要                                                                                           |

各段階に同じ比較範囲と該当ファイルを渡す。コードレビューと環境別の追加段階は読み取り専用とし、編集、依存追加、push、投稿を行わない。対象外や未実施の理由を記録し、差分の変化は [共通手順](findings.md) に従って再確認する。

動作確認の前提を確認できなければ、環境起動やログイン待ちをせず、未実施理由と手動確認手順を残して進む。
behavior には対象リポジトリ・PR または stack の範囲・環境・SHA と、操作、期待・実結果、判定、画像、未確認事項を構造化して返すよう依頼する。別の PR に起因する現象はレビュー候補から除く。
brief には同じリポジトリ・確認範囲・SHA の観測を渡し、結果の取り込みだけを依頼する。動作確認が未実施か対象が異なる場合は、理由と手順を資料に残す。brief の `-be` / `--behavior` は渡さない。

## 環境別の追加段階

このスキルの `SKILL.md` と同じディレクトリに Git 管理外の `work3.md` などを置く。
[作者向けの雛形](../../pr-author-all-review/work3.md.example) と同じ形式で、対象リポジトリと追加レビューを書く。
対象の照合や重複の扱いは [作者向けの手順](../../pr-author-all-review/references/stages.md#環境別の追加段階) に従い、このレビュアー用スキルのディレクトリから設定を読む。
