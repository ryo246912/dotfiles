# レビュー段階一覧

| 順序 | skill / 手順                   | 実行条件と役割                                                                                                                                                                                    |
| ---- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 直接レビュー・教訓照合         | [共通手順](findings.md) の直接確認と教訓照合で差分、関連コード、テスト、過去の指摘と規約を確認                                                                                                    |
| 2    | code-review                    | 同じ PR 差分を読み取り専用で確認できる場合に実行。利用できない場合は直接レビューに代替し、理由を報告                                                                                              |
| 3    | ponytail-review と専門レビュー | [作者向けの段階一覧](../../pr-author-all-review/references/stages.md) で共通列が「レビュアー」の行を順に使う。Ponytail は差分を確認。作者向け一覧の段階 10（pr-spec-review）の候補は段階 7 に集約 |
| 4    | 環境別の追加段階               | `work3.md` などの追加レビュー表で対象リポジトリと変更ファイルが一致する行を実行                                                                                                                   |
| 5    | pr-behavior-review             | 変更された振る舞いに動作確認が必要なら一度だけ実行し、到達経路・必要なデータ・画像を含む HTML レポートを作る。`-nb` / `--no-behavior` 指定時は対象外                                              |
| 6    | pr-brief                       | `-br` / `--brief` 指定時に解説を作り、段階 5 の確認結果を引き継ぐ                                                                                                                                 |
| 7    | 候補提示・壁打ち・投稿         | 裏を取った候補を提示。ユーザーの選択後に通常は draft を作る。公開は明示指定があれば No の確定後に追加確認なしで実行                                                                               |

各段階に同じ比較範囲と該当ファイルを渡す。pr-spec-review には関連チケットの ID・URL、取得できた要件や受け入れ条件、ユーザーが指定した要件も渡す。コードレビューと環境別の追加段階は読み取り専用とし、編集、依存追加、push、投稿を行わない。対象外や未実施の理由を記録し、差分の変化は [共通手順](findings.md) に従って再確認する。

`--select` 付きの段階 5・6 の実行指定は確定した選択に従う。起動済み環境・対象 SHA・操作権限などが揃わない場合も、behavior に読み取りで確認できた到達経路・必要なデータ・期待結果と未実施理由を HTML に残すよう依頼する。環境起動やログイン待ちをせずにレビューを進める。
behavior には対象リポジトリ・PR または stack の範囲・環境・SHA と、操作、期待・実結果、判定、画像、未確認事項、HTML レポートのパスを構造化して返すよう依頼する。別の PR に起因する現象はレビュー候補から除く。
候補提示時は段階 5 の実施状況を添え、HTML レポートを作成または引き継いだ場合にリンクを示す。対象外・未実施の場合やレポートを保存できなかった場合は、その理由を記録する。
brief には同じリポジトリ・確認範囲・SHA の観測を渡し、結果の取り込みだけを依頼する。動作確認が未実施か対象が異なる場合は、理由と手順を資料に残す。brief の `-be` / `--behavior` は渡さない。

## 段階 3 の実行確認

1. [作者向けの段階一覧](../../pr-author-all-review/references/stages.md) を実際に開き、共通列が「レビュアー」の全行を列挙する。各行について、差分に照らした適用条件と `--select` の選択結果を照合する。
2. 適用対象の各スキルは本文を開き、同じ比較範囲と該当ファイルを渡して個別に実行する。一般レビューや領域別エージェントの結果は、そのスキルの手順を実行したことを確認できる場合に実施済みとして扱う。
3. 候補提示時と最終報告で、各行のスキル名と状態（実施済み・対象外・選択外・未実施）を示す。指摘がなくても実施済みと記録し、対象外・選択外・未実施には理由を添える。正本を読めない場合、または適用対象かつ選択範囲内のスキルが未実施の場合は段階 3 を未完了と報告する。

## 環境別の追加段階

このスキルの `SKILL.md` と同じディレクトリに Git 管理外の `work3.md` などを置く。
[作者向けの雛形](../../pr-author-all-review/work3.md.example) と同じ形式で、対象リポジトリと追加レビューを書く。
対象の照合や重複の扱いは [作者向けの手順](../../pr-author-all-review/references/stages.md#環境別の追加段階) に従い、このレビュアー用スキルのディレクトリから設定を読む。
