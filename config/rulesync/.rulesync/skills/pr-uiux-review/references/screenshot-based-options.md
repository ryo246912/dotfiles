# 既存画面を基に代替案を作る

1. モックを作る前に、変更対象の既存画面をブラウザで開いて撮影する。PR では取得できる場合に変更前と現 PR 案の両方を撮影し、現 PR 案を代替案の直接の土台にする。新規画面に対応する既存画面がなければ、同種のタスクを扱う既存画面を撮影し、参照した画面を示す。
2. 比較する操作に合わせて、使用データ、画面幅、テーマ、画面の状態を揃える。対象画面のルートと撮影した状態を控え、必要に応じて操作の前後を撮影する。ユーザーに提示する画像には、テストデータを使うか機密情報・個人情報を伏せる。
3. 撮影画像を画像編集の参照または HTML モックの視覚的な土台として使う。既存のナビゲーション、レイアウト、書体、配色、コンポーネントを再現し、提案に必要な箇所を変更する。比較画像を撮影したら、参照画像と見比べて変更の意図が伝わることを確認する。
4. 「既存画面」「現 PR 案」「代替案」など実際の状態で画像にラベルを付け、撮影した元の画面と代替案を並べる。代替案は試作と明記する。同条件で撮影できなかった場合は、比較に影響する違いを添える。

実画面を開けない場合は、対象と状態を確認できる既存スクリーンショットを使う。これもなければ、既存のコンポーネントやデザインシステムを根拠にモックを作り、実画面の撮影ができなかった理由と参照した資料を示す。
