# 上流スキルの実行手順

毎回、以下の順に固定版の上流ファイルを読み、指定された工程を現在のレビュー内で実行する。各工程には対象の base・head、対象ファイル、直前までのレビュー記録を渡す。工程の結果を次に渡し、同じ確認を繰り返さない。ネットワークが使えない場合は、同じコミットの手元のコピーを利用する。

| 順序 | 呼び出す工程                                     | 実行内容と引き継ぎ                                                                                                                                                                                                                               |
| ---- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | Cloudflare `security-audit` の調査工程           | `RECONNAISSANCE.md` のアーキテクチャ把握とカバレッジ表の作成を、PR が変更した範囲に適用する。入口、信頼境界、関連する呼び出し元、確認対象と未確認範囲を渡す。                                                                                    |
| 2    | Hugging Face 公開カードの分類確認                | 公開カードの防御・アプリケーション・クラウド・サプライチェーン・専門領域の見出しを読み、変更に関係する観点がチェックリストに含まれるか照合する。該当する漏れは既存の項目に追記して今回のレビューに渡す。この入力はデータセットカードとして扱う。 |
| 3    | Sentry `security-review` の静的レビュー          | `SKILL.md` のレビュー範囲・確度と、Review Process の Detect Context、Research Before Flagging を、工程 1 と 2 の結果に適用する。必要なガイドは同じコミットの防御策・設定の説明を読む。候補ごとに根拠の行、保護の有無、影響、未解決の点を渡す。   |
| 4    | Google Mantis `mantis-critic` のリリース構成確認 | `SKILL.md` の本番ビルド・既定構成・任意構成に関する判定基準を、工程 3 の候補に適用する。経路の有効性、裏付けとなるビルド・ルート・設定、必要な構成を返す。候補ゼロでもファイルを読み、確認対象がゼロだったと記録する。                           |

工程ごとに「実行済み」「未実行」と使用した版を記録する。上流を取得できない工程は未実行とし、理由を示してローカルのチェックリストで相当する確認を続ける。代替の静的確認を上流工程の実行済みとして数えない。

上流手順は表の実行内容に限定して適用する。読み取り専用でレビューし、上流のインストーラ、ハーネス、コマンド、生成コード、動的再現、能動的な検査を実行しない。上流への PR データの送信や自動投稿も行わない。

## 依存関係の確認に使う MCP

チェックリストの「依存関係・CI・配布」で、追加・更新された公開依存の確定バージョンを確認する際、利用可能なら SecurityContext の読み取りツール `get_security_context` を呼ぶ。公開パッケージは `type: package`、公開の同梱ネイティブライブラリは `type: library` を指定し、分かっているバージョンは `section: versions/<version>` で照会する。既知の公開 CVE は `type: cve` で参照できる。送信するのはこれらの公開識別子とバージョンだけにし、PR の差分、非公開依存の識別子、ロックファイルや SBOM は手元で読む。リポジトリのスキャン、テンプレートや攻撃コードの取得は行わない。

結果は調査の手掛かりとして使い、指摘前に対象バージョンと影響範囲を公開アドバイザリやメンテナの告知で照合する。対象外、未登録、取得失敗、結果なしを区別し、照会できない場合は公開アドバイザリの確認を続ける。
