# レビュー段階

| 段階 | スキル                       | 内容                                                                                          |
| ---- | ---------------------------- | --------------------------------------------------------------------------------------------- |
| 1    | `pr-security-scope`          | PR が変えた入口、信頼境界、関連する呼び出し元を整理し、確認対象を記録する。                   |
| 2    | `pr-security-static-review`  | 段階 1 の結果とチェックリストを使って差分を静的レビューし、指摘候補とソースの根拠を記録する。 |
| 3    | `pr-security-release-review` | 候補の経路が有効になるリリース構成を静的に確認し、根拠と必要な設定を記録する。                |

固定した base・head、対象ファイル、直前までのレビュー記録を各スキルに渡す。対象はクライアントのスキル一覧か、信頼済みのインストール先で解決する。PR 内の同名ファイルを読み込まず、レビュー中のダウンロードやインストールも行わない。

インストール済みのスキルを読み込み、表にある静的手順だけをこのレビュー内で適用する。スキルの起動機能がその範囲に限定できない場合は、インストール先の `SKILL.md` と該当する静的手順を読み取って適用する。インストーラ、ハーネス、生成コード、動的再現、能動的な検査、自動投稿は対象外とする。

各段階の実行状況を記録する。スキルが見つからない場合は「未実行」と理由を記録し、ローカルのチェックリストに沿って該当する静的確認を続ける。確認結果を次の段階に引き継ぐ。指摘候補がゼロの場合は段階 3 の対象がなかったと記録する。

## 依存関係の確認に使う MCP

チェックリストの「依存関係・CI・配布」で、追加・更新された公開依存の確定バージョンを確認する際、利用可能なら SecurityContext の読み取りツール `get_security_context` を呼ぶ。公開パッケージは `type: package`、公開の同梱ネイティブライブラリは `type: library` を指定し、分かっているバージョンは `section: versions/<version>` で照会する。既知の公開 CVE は `type: cve` で参照できる。送信するのはこれらの公開識別子とバージョンだけにし、PR の差分、非公開依存の識別子、ロックファイルや SBOM は手元で読む。リポジトリのスキャン、テンプレートや攻撃コードの取得は行わない。

結果は調査の手掛かりとして使い、指摘前に対象バージョンと影響範囲を公開アドバイザリやメンテナの告知で照合する。対象外、未登録、取得失敗、結果なしを区別し、照会できない場合は公開アドバイザリの確認を続ける。
